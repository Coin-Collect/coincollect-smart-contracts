# Polygon release candidate

V3.5 uses the V3.4 Solidity sources. The release adds Studio economic preflight, execution and verification improvements, and a reproducible build. Existing V2 and V3 addresses keep their current behavior. This is an internal release candidate for independent review.

## NFT compatibility

| Chain | Standard | Release eligibility |
| --- | --- | --- |
| Polygon | Standard ERC-721 | Direct ERC-165 and bounded `ownerOf` checks. The collection must report current ownership faithfully. |
| Polygon | Managed ERC-1155 | Explicit admin approval, verified collection runtime and adapter, immutable hook binding, supported units and audited mint, burn, single and batch transfer paths. |
| Polygon | Ordinary ERC-1155 | Ineligible. Balance reads alone cannot preserve proportional reward rights across all transfers. |
| Base, Arbitrum | ERC-721 and ERC-1155 | Isolated journal fixtures only. Production remote participation is disabled. |

Evaluate proxy implementations, storage, upgrade authority, monitoring and emergency procedures separately. A proxy shell hash cannot establish implementation integrity. Collection hooks must execute synchronously before receiver callbacks and roll back the NFT transfer if accounting fails. The existing synchronous integration means an oversized enrolled batch, an unavailable adapter or an exhausted gas limit can revert the NFT transfer. Certification includes a gas budget, a batch-size limit demonstrated with worst-case tracked pools, and documented recovery. See the [V3.4 hook and ownership report](V3.4.md).

## Contracts and privileges

| Deployable | Role and trusted inputs |
| --- | --- |
| `ManagedRewardPositions` | Linked position accounting library. Verify its final runtime and every ledger reference. |
| `UniversalRewardsV33` | Polygon ledger for pool limits, NFT positions, caps, cumulative reward indexes, inventories and time-bounded recovery. The admin creates pools, manages funding controls and approves reviewed adapters. |
| `TreasuryVault` | Immutable ledger, owner and WPOL. The owner controls deposits, available withdrawals and pausing. The ledger records exact allocations, spends and returns. |
| `RewardSwapAdapter` | Approved exact-input swap paths against a pinned router and factory/pair relationship. The admin sets pair configuration, liquidity bounds and pause state. |
| `RewardRoutePlanner` | Admin approves assets, leaf adapters by runtime hash and bounded direct/two-hop candidates. Execution rechecks candidate eligibility and protected minimum. |
| `ManagedNftCollection` | Bound collection adapter for managed units. Pins the underlying runtime and source collection. The hook moves accrued credits proportionally at transfer time. |
| `FinalizedOwnershipVerifier`, `FinalizedNftJournal`, `NftSourceJournal` | Isolated verification and source journal artifacts. The Polygon release sequence excludes these. |
| `UniversalRewards` | Legacy V3 artifact and base contract. Keep legacy deployments and configuration versioned. |

Use one reviewed admin for the ledger, treasury and route governance. The separate POL-only executor holds no project funds, token allowances or administrative role. A person or bot can submit eligible permissionless checkpoints, observations, funding and recovery operations. Quote limits and a caller deadline remain enforced on chain.

## Accounting and threat model

- Vault available balance and outstanding allocations reconcile per asset with recorded deposits, spends, withdrawals and returns. A pool can consume only its own available allocation and configured reward lanes. Unsolicited transfers create no available budget.
- Deposits use exact transfers of supported ERC-20s or wrap native POL. Reject rebasing, fee-on-transfer, callback-dependent or otherwise incompatible tokens until separately reviewed. Read asset implementation, privileged controls and upgradeability before approval.
- Per-token liability and inventory are isolated by pool even when two pools use the same ERC-20. Accrual takes the lesser of threshold-adjusted emission and available inventory. Total paid rewards plus returned inventory must reconcile to funded rewards less attributable dust.
- Accrual stops at pool end. Current NFT ownership controls unclaimed rewards until the exclusive cutoff at `end + 30 days`. An expired reward cannot be paid by claim or paying exit. Budget return and expired inventory return are independent. Retry failed reward recovery per token.
- A fresh TWAP alone cannot establish a fair price in a weak market. Router, pair, token, intermediary and adapter identities, reserve thresholds, input share limits, TWAP age, spot/TWAP deviation, slippage and deadline all matter. Both production liquidity and continuing code identity require monitoring. Privileged token and proxy updates can invalidate an earlier review.
- Automation checks due tranches before spending POL on observations, uses transaction receipts and pool/token/epoch events, and defers on an executor's pending nonce. Parallel invocations can still race across processes or RPC views. The contract prevents a duplicate successful purchase for the same lane and epoch. A reverted or replaced transaction may still incur gas.
- Witness quorum compromise and source outages remain outside the Polygon trust boundary. The test-only remote journals model delayed and reordered evidence. They cannot prove completeness or finality independently. See [V3.4 reconciliation results](V3.4.md).

## Verified economics

Measurements use Polygon state pinned to block **97,638,790**, hash `0x9cf4791f6b4aab715d03aa5f66ad39e40676b80f00620927c6ddc6827db63419`. The signed transactions ran on fork chain **31337**. The 10 USDT, 365-day scenario spends the initial adaptive tranches and confirms real fork token balances after harvest and recovery.

| Operation | Gas used |
| --- | ---: |
| ERC-721 join, three rewards | 319,774 |
| Harvest, three rewards | 501,551 |
| USDT → WPOL, 0.246576 USDT | 384,548 |
| USDT → WPOL → COLLECT, 0.410959 USDT | 623,377 |
| USDT → WPOL → SHIB, 0.164384 USDT | 625,904 |
| Eight TWAP observations combined | 689,044 |
| Recover budget | 155,561 |
| Expired reward recovery, each token | 144,945–154,130 |

A 30-day horizon yields 13 modeled replenishment windows. Repeating the measured three purchases and eight TWAP calls in all 13 windows gives **30,197,349 gas**, about **0.906 POL** at 30 gwei or **6.039 POL** at 200 gwei. This extrapolation assumes purchases and observations in every window. A stable quote, shared observations, ample inventory or a single consolidated purchase can reduce cost. Fallbacks, retries and market changes can increase costs or disable purchases. Gas-only spending is separate from the lifetime reward budget.

| Equal positions | Gross funding equivalent per NFT | Join + harvest at 30 gwei and $0.25/POL | Join + harvest at 200 gwei and $0.50/POL |
| ---: | ---: | ---: | ---: |
| 4 | 2.500000 USDT | $0.0062 | $0.0821 |
| 100 | 0.100000 USDT | $0.0062 | $0.0821 |
| 1,024 | 0.009765 USDT | $0.0062 | $0.0821 |

Each row assumes full enrollment for the whole period, adequate reserves and a met wallet threshold. Studio applies the existing threshold ratio and compares equal power to one high-power NFT among lower-power NFTs. Costs use reference exchange rates. Actual rewards are delivered in their configured tokens, at variable prices. Treasury purchases are deferred when estimated execution fees exceed the lesser of 0.25 POL or 5% of protected POL value. Studio uses a rounded gas allowance and a live protected quote at the purchase size when available.

## Reproduce and verify

From this project directory on Node 22:

```sh
npm ci --workspaces=false --ignore-scripts
npm run --workspaces=false compile
npm test --workspaces=false
release_dir=$(mktemp -d)
node scripts/build-release.cjs "$release_dir"
cmp release-manifest.json "$release_dir/manifest.json"
node scripts/export-abi.cjs "$release_dir/frontend-abi.ts"
cmp "$release_dir/frontend-abi.ts" ../../../coincollect-frontend/src/features/universalRewards/abi.ts
COINCOLLECT_V34_FIXTURE=1 COINCOLLECT_RELEASE_FORK_MANIFEST="$release_dir/polygon-fork.json" npm run --workspaces=false test:polygon-fork
```

The [source release manifest](release-manifest.json) pins the compiler, dependencies, standard JSON input, creation/runtime templates, link and immutable references and ABI hashes. CI publishes the full standard input, per-contract artifacts and generated frontend ABI. The pinned fork produces a separate deployment record with exact constructor arguments, runtime hashes, immutable slots, external token/router/factory/pair runtimes, transaction evidence and gas measurements. Runtime comparisons validate the exact linked runtime outside compiler-declared immutable locations. The record does not certify addresses formerly deployed or intended for mainnet.

Before a separately authorized rollout, follow the [operations runbook](V3.5-operations.md). Independent blockers include accounting and hook review, collection-specific and token-specific certification, real configuration and ownership review, DEX market assumptions, and operator incident drills. Fork and browser results establish candidate behavior in isolated environments.


## V3.5.1 compiler and deployment tooling

The toolchain uses Node 22, Anvil 1.7.1, OpenZeppelin Contracts 5.4.0, ethers 5.8.0 and solc 0.8.30. The npm lockfile overrides the solver's `tmp` dependency to 0.2.7 and the ethers provider's `ws` dependency to 8.23.0.

- `tmp` is reachable through solc's optional SMT subprocess helper. The release uses standard JSON compilation with reviewed sources, calls no external solver, and supplies no user-controlled temporary-file names. The override secures the installed helper while preserving the exact compiler.
- `ws` is reachable when an ethers WebSocket provider connects to a peer. Release scripts use HTTP JSON-RPC and run signed fixture transactions against loopback Anvil. The ws 8.x patch secures the installed transport without migrating ethers or changing Solidity inputs.
- The package audit reports zero critical, high and moderate findings. Fourteen low-severity dependency findings remain in the ethers/solc toolchain. Re-run `npm audit --workspaces=false --audit-level=high` before using the release tooling. [tmp advisory](https://github.com/advisories/GHSA-ph9p-34f9-6g65) · [ws advisory](https://github.com/advisories/GHSA-96hv-2xvq-fx4p)
- Compared against V3.5 contract commit `b375dddeac4c3d11f1ad1ced9288e1f10eb7e56e`, the manifest's standard-input digest and all ten contract artifact records are identical. The lockfile digest reflects the two patched tool dependencies. Source, bytecode, ABI, constructor requirements, privileges and deployment order remain the V3.5 release candidate described above.

The earlier [verified V3.5 frontend](https://github.com/Coin-Collect/coincollect-frontend/commit/e6daf6c98d8a2f20e495a30f4d5f1ff16cb11f4a) is the baseline for the V3.5.1 platform migration.
