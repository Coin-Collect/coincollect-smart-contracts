# Polygon deployment and incident runbook

## Pre-deployment

1. Record the commits for both `pool-management` repositories. Download the Solidity and Polygon fork CI artifacts. Reproduce the checked release manifest, compare the frontend ABI byte for byte and confirm the pinned Polygon fork checks passed.
2. Obtain an independent review of reward conservation, Treasury isolation, claims at the exact cutoff, managed transfer dependencies, transitive asset/collection trust and role assignments. Record the reviewed mainnet transaction plan and separate deployment authorization.
3. Use a chain-137 read-only RPC to recheck Polygon, the wrapped asset and all token, router, factory and pair identities. Compare against authorized runtime hashes. For proxies verify the implementation, upgrade authority, current implementation runtime and monitoring plan. Establish real trade-size evidence, price impact limits and TWAP observations for each route. A stale or missing quote is a release blocker for that route.
4. Confirm a single intended admin and a separate gas-only account. Keep private keys, authenticated RPC URLs and the cron secret in the authorized secret store. Never commit a signer, a credentialed URL or a wallet dump. Keep Vercel execution disabled while verifying the deployment.

## Exact dependency order for an authorized rollout

1. Deploy `ManagedRewardPositions` and record its exact runtime hash and deployment receipt.
2. Deploy the approved `RewardSwapAdapter` leaves using admin, router, expected router hash, factory and WPOL. Deploy `RewardRoutePlanner` using admin and WPOL. Set supported assets, approve each leaf by verified runtime hash, configure audited pairs and then enable planner paths. Verify live quotes after observations at a valid interval.
3. Link the verified library address into `UniversalRewardsV33` and deploy with admin, supported assets, WPOL and planner. Confirm chain ID, admin, treasury owner, WPOL, planner and zero remote verifier. Preserve the existing deployments.
4. Deploy `TreasuryVault` with the ledger address. Verify ledger, WPOL and the immutable owner, then use `attachTreasuryVault` and verify the one-time binding.
5. For each approved managed ERC-1155, deploy a `ManagedNftCollection` with the verified ledger, Polygon source, underlying collection, ERC-1155 standard, maximum permitted units and zero journal. Bind the reviewed collection hook. Confirm both sides of the binding and exact runtime before calling `approveManagedCollection`. Review every relevant transfer path and enrolled batch limit.
6. Record each deployment transaction, constructor encoding, linked creation code, full runtime hash, chain and block, immutable getters and governance configuration. Verify explorer standard JSON source, license and compiler settings. Compare a fresh RPC read to the authorized manifest before configuring `NEXT_PUBLIC_V3_LEDGER_ADDRESS` and `NEXT_PUBLIC_V3_LEDGER_CODE_HASH`. Keep Base and Arbitrum participation disabled.
7. Only after separate operational approval, verify Vercel cron authorization, alerts and least-privilege roles. Executor setup uses `COINCOLLECT_V3_EXECUTOR_RPC`, `COINCOLLECT_V3_EXECUTOR_ADDRESS`, `COINCOLLECT_V3_EXECUTOR_KEY` and `CRON_SECRET` in the secret store. Activation switches are `COINCOLLECT_V3_AUTOMATION=polygon` and `COINCOLLECT_V3_ENABLE_POLYGON_EXECUTION=1`. The executor needs a small POL gas reserve and no reward tokens or token allowances. Record the correct `COINCOLLECT_V3_AUTOMATION_FIRST_POOL` when using separate generations.

## Operations and incidents

| Condition | Action and verification |
| --- | --- |
| Unsafe market, mismatched code or suspect router | Disable off-chain execution and pause the planner or affected leaf. Check current code, governance, reserves, route configuration and prior receipts. Re-enable only reviewed routes with fresh protected quotes. |
| Treasury exposure or suspicious solvency | Pause the vault with the admin and disable execution. Reconcile available, allocated, spent and returned amounts against exact asset transfers. Pausing prevents deposits, allocations, purchases and withdrawals. Valid claims and on-chain returns remain available subject to the contract and token. |
| Pool-specific issue | Pause the affected pool's funding. Preserve claim access and communicate the exact chain deadline. If a token blocks recovery, retry that token separately after the restriction is resolved. |
| Missing receipt or repeated cron job | Keep the hash and record pool, token and epoch. Check receipt, finalized block, event and current lane state from healthy RPCs. Reconcile the executor nonce before resuming. Concurrent Vercel instances can race and one attempt may spend gas while reverting. |
| RPC, Vercel or market outage | Check a known good read endpoint against the latest confirmed state and compare chain and runtime. Keep executions disabled while evidence is stale. Restart with fresh quotes and current epochs. Missed windows can leave inventory underfunded and rewards lower. |
| Expired obligations | After pool end, use `recoverBudget`. At or after the claim cutoff, call `recoverExpiredRewards` per token. Confirm receipts and exact Treasury return events with remaining inventory and available balance. Withdraw only recorded available balance using the admin. |
| Managed NFT transfer failure | Verify collection binding, runtime and adapter state. Estimate on a fork and reduce the transfer batch when possible. Do not bypass the hook. Escalate unresolved reverts to the collection maintainer and security reviewer. |

Record symptoms, block and transaction hashes, affected assets or pools, owner approval and recovery evidence. Keep sensitive configuration out of logs. Monitor executor POL balance, cron status, pending receipts, unpurchased reward coverage, unavailable quotes and unsettled balances.
