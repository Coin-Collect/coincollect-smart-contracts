# Universal Rewards V3.6 audit candidate

V3.6 adds an asset registry, Treasury swaps and native POL withdrawals. Deployments are versioned. V2 and the frozen V3.5.4 ledger, vault, ABI, manifest and deployments continue to operate at their existing addresses. Existing pools retain the same reward token addresses, caps and accrued rights. A V3.6 deployment starts with its own pools and Treasury accounting. Any future migration of an existing Treasury balance is a separate authorized operation.

## Security model

- One admin owns the ledger, asset registry, vault and route planner. The existing gas-only executor retains only permissionless pool settlement operations. Treasury trades and native withdrawals require the owner.
- The registry accepts up to 64 distinct reviewed Polygon ERC-20 addresses. It binds token runtime, decimals (0–36), reviewed evidence hash and an exact round-trip probe. It independently toggles Treasury deposits and new budget funding, new reward eligibility and use in swaps. Adding or restoring permissions rechecks identity.
- Proxies with a supported public implementation getter pin both shell and implementation address/runtime. A changed identity stops new uses. The UI checks ERC-1967 and legacy slots, and refuses known beacon/minimal proxies or a discovered implementation with no matching public getter. Unknown proxy patterns, deceptive contracts, privileged mint, blacklist, pause, fees, rebasing and upgrades require manual source and governance review. A successful probe does not certify future behavior. Re-review requires all permissions to be disabled and preserves the token's original decimals.
- Existing allocations, direct reward funding, entitlements, paying exits, claims and recovery are not reauthorized by registry permission changes. Converting a pool budget still requires an eligible path, including intermediate eligibility. Governance can quarantine an asset or pause the planner. This can defer a pool's future purchases. It does not redirect or erase committed credits.
- Vault swaps spend only the `available` book balance. Allocated tokens are physically in the ledger. Reward inventory and NFT liabilities remain independently accounted for there. Direct token transfers to the vault create no credit. Deficient physical balances cause debits/swaps to fail closed.
- The configured route index is executed atomically. The planner checks token permissions, adapter runtime hashes and exact balances for each hop. Its existing direct/two-hop bound remains in force. Leaf adapters verify router/factory/pair, minimum reserves, 50 bps maximum input share, fresh observations, spot deviation and their protected quote floors. The vault also enforces a nonzero caller minimum and a maximum five-minute deadline. Allowances are exact and cleared after success. Failed transactions roll back the ledger, balances, approvals and logs.
- For each token, `available + allocated = deposited + rewardsReturned + swappedIn - spent - withdrawn - swappedOut`. Returned funding cancels an outstanding allocation. The invariant excludes untracked donations. Native withdrawal burns exactly the reviewed WPOL quantity, checks the received POL and pays only the immutable owner under the vault's reentrancy guard.
- On Polygon, verify and monitor token/source identity, proxy governance and independently approved route parameters before granting permissions. Consider reserves, stablecoin bridge and issuer risk, TWAP freshness, size, fees and MEV. Preview does not guarantee a future fill.

[ERC-1967 storage conventions](https://eips.ethereum.org/EIPS/eip-1967) and [OpenZeppelin SafeERC20](https://docs.openzeppelin.com/contracts/5.x/api/token/erc20#SafeERC20) describe the underlying standards and token call wrappers.

## Reproduce and pair the artifacts

Solidity remains 0.8.30. V3.6 builds use the Shanghai EVM target, via IR and optimizer runs 1. The V36-specific compiler extension checks frozen source preimage hashes, supplies narrow asset/attachment and planner hooks, and drops unreachable remote-seat writes from the Polygon-only resolver. Settlement functions, position storage layout and the four-reward limit are retained. The generated standard JSON includes every source exactly as compiled. Normal V3.5 artifacts retain their previous input and optimizer settings. The V3.6 ledger runtime fits the EIP-170 limit at 24,183 bytes.

```sh
npm ci --workspaces=false --ignore-scripts
npm test
release_dir="$(mktemp -d)"
node scripts/build-release.cjs "$release_dir" 3.6-rc
cmp release-manifest-v36.json "$release_dir/manifest.json"
node scripts/export-v36-abi.cjs "$release_dir/frontend-abi.ts"
COINCOLLECT_V36_FORK_MANIFEST="$release_dir/fork.json" npm run test:polygon-fork:v36
```

[Immutable release manifest](release-manifest-v36.json) pins the source input, bytecode templates, ABIs, link references and immutables. Contracts CI publishes those artifacts plus a separate fork manifest with deployed hashes, constructor parameters and transaction evidence. Frontend CI compares both V3.5 and V3.6 generated ABIs and tests each version against `next start`.

Recommended verification sequence on an authorized future deployment:

1. Verify the single admin and approved WPOL identity. Deploy `TreasuryAssetsV36(admin)`.
2. Deploy `RewardRoutePlannerV36(registry, WPOL)` and the statically linked `ManagedRewardPositions` library. Deploy `UniversalRewardsV36(planner)`, then `TreasuryVaultV36(ledger)`, and attach it with the same admin.
3. Register each reviewed asset with the documentary hash and a small exact probe. Review bridge, compatibility and privileged roles. Approve routes and their input/intermediate/output assets in the planner.
4. For each leaf, use a reviewed `RewardSwapAdapter(admin, router, routerCodeHash, factory, WPOL)` compatible with the target market. Verify and configure the pair runtime and minimum reserves by direction. Approve each adapter runtime and each direct/two-hop path. Record two valid observations before supplying a quote.
5. Bind managed collection adapters to the new ledger and verify their hooks. Verify linked runtime and every immutable before changing the application ledger address and hash. Run the Treasury, permissions and incident drills in an isolated chain first.

## Independent review

The frozen audit and runbook remain in [V3.5.4](V3.5.4.md) and [V3.5 operations](V3.5-operations.md). Add independent examination of the V36 compiler extension, registry proxy handling, exact-transfer probe limits, balance reconciliation, registry/planner/vault trust relationships, native withdrawal boundary, route indexing and maximum gas under adverse tokens. Test the admin's incident process for quarantining a token, disabling paths and pausing the vault/planner while allowing recovery. Confirm the final approved route configuration and live observations on the intended deployment. Mainnet release is pending those assessments.
