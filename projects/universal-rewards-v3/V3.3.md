# Universal Rewards V3.3

V3.3 is a new Polygon settlement ledger. Existing V3.2 ledgers and V2 pools keep their deployed rules. Pool schedules, reward inventories, lifetime funding, route controls and Treasury accounting remain in one ledger. The CoinCollect admin wallet owns the ledger and vault. Receipts and payouts remain on Polygon. [V3.2 funding and deployment](README.md)

| Source | ERC-721 | ERC-1155 |
| --- | --- | --- |
| Polygon 137 | Standard live `ownerOf`, without custody | Reviewed collection with a bound transfer hook |
| Base 8453 | Isolated journal and explicit source intent | Isolated journal, transfer hook and explicit source intent |
| Arbitrum One 42161 | Isolated journal and explicit source intent | Isolated journal, transfer hook and explicit source intent |

V3.3 rejects production remote verifier and adapter deployments on Polygon. The isolated ledger has chain ID 31337 and runs the same Treasury and reward accounting. Custom Polygon ERC-1155 support also requires a review of the bound hook, collection implementation and bytecode before real assets are used.

## Ledger and quantity rules

- `UniversalRewardsV33` uses the existing reward-per-power indexes and a statically linked `ManagedRewardPositions` library. Per-wallet positions, distinct addresses, participating units and effective power are separate. Per-pool and per-wallet reads remain paged. A normal checkpoint does work proportional to the number of reward tokens.
- `ManagedNftCollection` binds a single canonical (source chain, collection) identity and NFT standard. The ledger accepts one adapter per canonical pair. A position ID includes the pool, underlying token ID, wallet and whether funds were released. Pool configuration binds unit power and the adapter. Pool Studio can set an active-unit limit per token ID and wallet before the start.
- Polygon ERC-1155 transfers are reported inline by the reviewed collection, after its balances change and before the transaction completes. Both transfer event shapes, minting and burning use the same source hook. The protocol never requests custody, transfers an NFT or obtains an NFT allowance.
- Transfers consume entitled units first, then unregistered units. For a wallet with 10 owned and 6 participating units, sending 2 moves 2 entitled units and one third of their scaled outstanding credit. The sender keeps 4 participating units. If the receiver has capacity, it gains 2 active units. Above a position or unit limit, accrued rights still follow the moved units, while excess units contribute no power. ERC-1155 copies have no individually traceable identity. The policy assigns credit proportionally over the entitled units in each wallet. It rounds moved credit down and leaves the remainder in the sender’s entitlement.
- Partial exit releases that proportion of earned credit to a wallet-specific payout position without moving NFTs. Burning an entitled unit relinquishes its share to the pool's uncommitted reserve. Minted or received units never give duplicate power. New units can be enrolled up to the verified live balance and both limits. At pool end the accumulator stops. Eligible credits can move or be released until the exact 30-day payout boundary. Expired inventory returns to Treasury per token.
- A managed collection can have eight pools in its transfer hook at once, through the close of each claim window. The limit bounds the work required for each transfer on a supported collection. It does not limit the total number of pools in the ledger or positions in a pool.

## Remote verification and settlement limitations

`NftSourceJournal` records ordered transfers and holder-authorized requests. The reviewed collection must report every relevant mint, burn and transfer from activation. A request reads `ownerOf` or `balanceOf` in the same source transaction. The remote adapter never returns a payable owner for a live remote seat. A finalized `Release` or `Exit` intent explicitly moves credit into a Polygon payout position. A transfer ordered before that intent moves the rights first. A later transfer carries remaining rights after that already authorized release. A reusable ownership certificate cannot trigger a payout.

`FinalizedNftJournal` consumes up to 32 contiguous entries per batch, binds the source journal and adapter into the EIP-712 domain and digest, rejects replay, older checkpoints, conflicting hashes at the same height, and stale evidence. The witness helper independently checks at least two distinct RPC identities for chain ID, finalized block/hash, predecessor checkpoint, pinned source bytecode, hook binding and canonical event sequence. A majority quorum verifies this off-chain evidence. The tests use two separately queried clients pointing at each simulated chain. They do not prove independent provider behavior in production. Each signed batch is accepted only on isolated settlement chain 31337. [ERC-1155](https://eips.ethereum.org/EIPS/eip-1155) · [Canonical block reads](https://eips.ethereum.org/EIPS/eip-1898) · [Arbitrum finality](https://docs.arbitrum.io/build-decentralized-apps/troubleshooting-building)

Remote changes affect reward power when Polygon applies the ordered journal. During relayer delays or an outage, checkpoints still use the last accepted positions. The affected interval can be as long as the delay. This model cannot reconstruct exact source-time shares when transfers from multiple chains arrive at different times. A user intent more than two hours old is skipped and logged for retry. Stale transport, a reorg conflict, or a failing transfer does not create a new payout authorization. The admin can pause a stream to freeze both relay and released payouts during an investigation. A conflicting finalized history requires investigation and reconciliation of all existing settlement liabilities before any rollout. Witness quorum compromise can forge source facts. Production needs a reviewed trust model, independent provider and signer infrastructure, loss and outage procedures, and an audited settlement policy for delayed cross-chain weights.

Local testing uses free loopback Anvil instances. A remote flow needs source gas for a request, Polygon gas for a batched relay, and Polygon gas to claim the released balance. There is no per-claim asset bridge. Future operating cost depends on RPC availability, witness operations and gas. The source wallet must also control its Polygon payout address. Production schedules, credential provisioning and distribution are disabled.

## Reproduction

```sh
npm ci --workspaces=false --ignore-scripts
npm run --workspaces=false compile
npm test --workspaces=false
COINCOLLECT_V33_FIXTURE=1 npm run --workspaces=false test:polygon-fork
COINCOLLECT_V33_FIXTURE=1 node scripts/deploy-browser-fixture.cjs
```

The fixture requires loopback Anvil on 31337. It emits the linked ledger address, runtime hash and an approved Polygon ERC-1155 collection. The separate integration starts Base and Arbitrum Anvil nodes on 8453 and 42161, emits source-side events, collects finalized evidence and signs a quorum for the isolated ledger. `scripts/finalized-journal.cjs` builds unsigned proof material for independent witnesses. It does not persist signer keys or automatically broadcast.

Use `scripts/export-abi.cjs` to reproduce the Solidity ABI artifact. For any future authorized deployment, verify the linked library address and runtime hash alongside the ledger, approved adapters and vault. There is no in-place migration.
