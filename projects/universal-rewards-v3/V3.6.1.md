## Threat model and accounting

| Boundary | Invariant and evidence |
| --- | --- |
| Treasury available, allocations and payouts | For each token, available plus allocated equals deposits plus reward recoveries plus swap credits less spend, owner withdrawals and swap debits. Allocations are held in the ledger by pool. The vault checks actual balances and exact transfer deltas. ERC-20 donations create no book credit. Seeded transitions over three pools check the ledger and solvency after each operation. |
| Ledger and claims | Committed reward units remain attributable to the correct pool. Swapping or recovering a sibling pool's funds leaves them intact. At exactly pool end plus 30 days claims close. Recovery is token-specific and idempotent. Managed ERC-1155 transfers carry proportional rights. Seeded partial transfers, duplicate actions, boundary UTC blocks and recovery compete against the same local token books. |
| Temporary approvals | V3.6.1 checks the actual allowance after setting and after clearing each ledger-to-planner, vault-to-planner, planner-to-adapter and adapter-to-router allowance. A nonstandard approval result reverts the entire transaction, including budgets, inventory, swap totals and balances. The planner also revalidates path policy at execution after receiving input. |
| DEX execution | Pair, router and adapter identities, reserve floors, trade-size caps, fresh TWAP, price drift, a caller minimum and a short deadline bound execution. Two-leg swaps revert as a unit. The execution floor limits worst-case fill but leaves room for price movement and sandwiching within the tolerance. Public observation age does not prove the adapter has live observations. |
| Token and proxy trust | Permission bits and exact transfer checks mitigate accidental incompatibility. Arbitrary tokens can spoof views or change behavior after admission. A pin freezes the recognized implementation identity for new uses, while economic powers such as pause, blacklist, upgrade, bridge minting and admin changes remain external. Verify upgrade and mint authorities from source and governance evidence. |
| Native POL | The single admin withdraws only available WPOL. Unwrap checks the approved asset and both balance deltas, then sends the exact POL to the immutable owner. A rejecting recipient reverts settlement. Review admin contract receive behavior before using a contract wallet. |
| Signers and RPC | The owner controls registration, routes, pool plans and vault withdrawals. Compromise can spend available Treasury assets and change approvals. The gas-only executor can perform only permissionless settlement under the same on-chain policy. The frontend rechecks account, chain, runtime, balance, simulation and confirmed receipts. Local writes also compare the wallet RPC's block hash to the expected loopback fork. |

Known residuals include loss of value or liveness from issuer action, erroneous administration, an unrecognized proxy pattern, weak venue liquidity, a malicious managed NFT hook, stale or inconsistent RPC data, MEV and coordination with the sole admin. None of these are covered by an independent audit in this package.

## Reproduction and incident procedure

```sh
npm ci --workspaces=false --ignore-scripts
npm audit --workspaces=false --audit-level=high
npm test --workspaces=false
artifacts="$(mktemp -d)"
node scripts/build-release.cjs "$artifacts" 3.6.1-rc
cmp release-manifest-v361.json "$artifacts/manifest.json"
node scripts/export-v36-abi.cjs "$artifacts/frontend-abi.ts"
COINCOLLECT_V34_FIXTURE=1 npm run test:polygon-fork
COINCOLLECT_V36_FORK_MANIFEST="$artifacts/fork.json" npm run test:polygon-fork:v36
node scripts/polygon-market.cjs 97756337
```

The market script takes an optional read-only archive endpoint via `COINCOLLECT_V3_POLYGON_RPC`. A missing historical observation is reported per direction. Tests use isolated forks and test funds. Keep any deployment credentials, production RPC URLs and cron secrets outside artifacts and Git. Ethers 5 in Solidity tooling still inherits [an Elliptic advisory](https://github.com/advisories/GHSA-848j-6mx2-7j84) classified low by npm. Reproduce artifacts offline and use an independently reviewed signer for any authorized future production transaction.

For a token, path or data incident, stop automation first and save block numbers, transaction receipts, reported allowances, asset and pool balances, permission changes and code hashes. The admin can pause the planner and vault, disable affected routes and quarantine token permissions. Claims and deadline-driven ledger recovery follow the existing contract rules. Reconcile reported liabilities and physical holdings across every affected pool before any restore. Test restoration with exact fork receipts and fresh observations. A sole-admin compromise requires following the governance incident procedure and an independently authorized migration decision.

| Release gate | Decision |
| --- | --- |
| Source, ABI and artifacts match. Solidity, fork and application acceptance pass | Submit to independent review on the exact paired commits |
| Independent protocol audit and remediation review | Required before production |
| Current token implementation, bridge and admin evidence and live approved DEX/TWAP | Required for each production asset and route |
| Admin and gas-only executor control, operational alerting, wallet sign-off and recovery drill | Required before enabling production |

The current mainnet release decision is **NO-GO** pending the independent audit and production-specific acceptance and governance checks.
